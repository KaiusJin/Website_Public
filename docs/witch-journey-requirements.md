# 魔女旅行个人网站：详细需求

更新日期：2026-09-15  
阶段：需求与计划；本轮交付为文档，不代表功能、数据库或部署已完成。  
配套文档：[实施计划与后台改造](witch-journey-implementation-plan.md)

## 1. 产品目标与范围

访客操控一位正常动画比例的旅行魔女，穿过一张超长横向地图，在旅途中认识 Kaius 的学习、工作、项目、技能、成就和个人兴趣。整体保留《魔女之旅》的安静、梦幻、旅行与见闻记录的气氛。

首版最终交付是七个场景完整串联的可用网站。单场景样板是开发过程中的验证步骤，不能作为完整交付。

### 1.1 已确认决策

| 编号 | 要求 | 决策 |

### 1.2 用于规划的默认方案

以下是工程与产品建议，可依据用户后续回答调整；不冒充已确认事实。

- 新入口使用 `/journey`，现有 `/` 保持不变。
- 双语范围首先覆盖探索版全部界面及内容；经典版保持当前语言和布局，共用兼容的数据结构。
- 手机与 iPad 竖屏暂停游戏，展示旋转提示和经典版入口；恢复横屏时继续原位置。
- 已确认自由飞行与随时降落；世界边界、无体力限制和安全落点规则按下文建议实施。
- 行走、跳跃、飞行用于探索；首版无战斗、死亡惩罚或强制收集解锁。
- 七个地点均可通过旅途目录直接访问，完整经历和项目不受操作技巧限制。
- 新增个人内容使用真实资料；没有资料时不编造故事，不展示假日记。
- 简历下载使用真实文件或现有有效链接，文件待确认。

## 2. 参考与视觉语言

### 2.1 体验参考

- [Susan Ho](https://susan-ho.vercel.app/inside)：插画人物、画廊环境，以及融入环境的 Skills、Experience、Projects、About 入口。
- [Jiamu Shangguan](https://mu142857.github.io/index.html)：游戏式探索、操作提示，以及 Classic Site 入口。

前者用于场景与内容结合，后者用于探索操作和双版本入口。参考站的全部功能不自动成为需求。

### 2.2 画面要求

- 2D 横向动画插画，柔和光影，可带少量水彩质感。
- 正常比例的浅发魔女作为当前角色方向，帽子、深色斗篷、扫帚、皮箱或日记本形成旅行识别。
- 角色脸部、服饰、比例和扫帚在不同动作中保持一致。
- 画面分远景、中景、地面与前景，兼顾宽屏和窄横屏取景。
- 天空、草原、欧式小镇、木质图书馆与星夜逐步过渡；相邻区域有道路或建筑衔接。
- HUD（屏幕固定界面）轻量，文字和按钮与背景有足够区分。
- 中文和英文由界面渲染，不把需要切换语言的文字烘焙到场景图中。

| 场景类型 | 色彩方向 |
| --- | --- |
| 小屋、清晨草原 | 米白、浅绿、浅蓝 |
| 小镇 | 暖黄、木色、红屋顶 |
| 图书馆、学院 | 深木色、金色、适量紫色 |
| 湖畔、终点 | 深蓝、银白、淡紫 |

### 2.3 素材制作要求

- 制作阶段搜索角色姿势、服装、场景和光影参考，保存来源记录。
- 不强制原创；是否直接采用具体原作角色尚未指定，先按旅行魔女形象规划。
- 用户指定的模型名称原样记录为“gpt image 2.5”。当前已知图像工具没有显式模型选择参数；制作时核实可调用能力，不能把未确认的模型版本写成已使用。
- 先建立角色设定图和统一场景风格，再制作动画帧与七区素材。
- 动画至少包含待机、行走、起跳、空中、落地、骑乘、飞行待机、飞行移动、降落。
- 素材需要可用的透明边缘、统一锚点、合理切片与尺寸；生成结果逐项检查，不能把静态图片平移当作全部角色动画。
- 场景按可拼接图层与区块组织，不将整张超长地图作为单张巨大图片加载。
- 保存原图、运行时压缩图、来源与生成记录；具体文件格式和尺寸在样板性能检查后锁定。

| --- | --- | --- | --- |

| meadow | 草原小路 | About、Waterloo CS、方向与个人兴趣 | 路牌、野餐物件或日记页打开资料，道路通往小镇 |
| town | 小镇街道 | 全部公开 Experience | 建筑/门牌对应经历，数量增加时使用街区目录或复用建筑，不截断资料 |
| library | 魔法图书馆 | 全部公开 Projects | 书籍或书架对应项目；按数据数量展示书架目录，支持查看详情及外部链接 |
| academy | 魔法学院 | 语言、Backend、AI Agent、Cloud/Infra 等 Skills | 卷轴、装置与法阵对应分类，穿过学院抵达夜景 |

### 3.1 内容字段

- About：教育、方向、简介、地点、兴趣；正式事实以现有资料或用户补充为准。
- Experience：名称、职位、起止时间、当前状态、工作要点、技术、链接。
- Projects：项目名称、简介、贡献、成果、技术、截图、GitHub 与演示链接；没有链接时隐藏对应按钮。
- Skills：分类和技能标签；专有名称不强行翻译。
- Awards：名称、组织、年份、描述与证书链接。GPA 仅在用户确认后添加。
- Personal：已确认摄影、旅行、日常记录、音乐；支持图集/照片说明、旅途记录、日常短文、曲目或歌单链接。可散落在草原、图书馆、湖畔，无需强制新增第八场景。
- Contact：复用现有已公开的真实联系方式。
- 内容面板保留正式名称和技术细节；魔法比喻用于章节标题和引导语。

前期提到的 Jinrui Technology、CraneLab、Ground News、WeCanFindIntern、NoteFlow、UW Degree Explorer、CausalEdge 是候选内容。代码检查不能证明这些就是当前数据库中的完整清单，实际列表需读取公开资料或由用户确认。

### 3.2 发现与阅读

- 靠近物件出现高亮和交互提示；点击、触摸或按交互键才打开详情。
- 同时有多个附近目标时，突出当前目标，避免一次触发多个面板。
- 面板打开后暂停移动与物理，解除所有按住的输入；长内容独立滚动。
- 关闭后恢复原地点，避免仍在漂移或自动跳跃。
- 从飞行中打开目录或面板时保持安全状态，关闭后恢复规则一致。
- 目录可直接定位七个章节，并可直接进入项目、经历、简历等阅读内容。

## 4. 操作规则

### 4.1 键鼠操作建议

| 输入 | 地面 | 骑扫帚 |
| --- | --- | --- |
| A/D 或左右方向键 | 左右走动 | 左右飞行 |
| W/S 或上下方向键 | 不触发跳跃 | 上升/下降 |
| Space | 单次跳跃 | 预留，不重复触发跳跃 |
| F | 骑上扫帚并起飞 | 发起安全降落 |
| E / Enter | 与附近物件交互 | 与允许空中交互的目标互动 |
| Escape | 关闭最上层面板，或打开暂停菜单 | 同左 |
| 鼠标 | 点击场景物件、目录与面板 | 同左 |

键位是建议默认值；操作提示需与实际实现保持一致。

### 4.2 触控操作

- 左下虚拟摇杆，右下跳跃、扫帚/降落、交互按钮。
- 地面只使用摇杆横轴控制行走；飞行使用两轴。
- 需要多指同时输入：左手持续移动时，右手能跳跃、骑乘和交互。
- 设置摇杆死区；松手、移出后取消、浏览器中断触摸时归零。
- 飞行状态下跳跃按钮隐藏或禁用并保持布局稳定；扫帚按钮切换为降落。
- 触控目标建议至少 48 CSS px，避开安全区和系统手势边缘。
- 只在游戏操作区域处理触摸手势；阅读面板仍可正常纵向滚动。
- iPad 外接键盘时支持键盘操作，触控控件可手动显示/隐藏。

### 4.3 跳跃、飞行与地面

- 单次跳跃、重力、落地检测是首版要求；二段跳和冲刺不是当前承诺。
- 默认加入短暂的跳跃输入缓冲与边缘容错，具体数值通过手感验证调整。
- 骑乘和飞行是独立动作状态，具有实际高度变化和飞行动画。
- 已确认自由飞行；实施规则为水平与垂直边界内移动，不能穿出地图，飞行高度上限按场景设置。
- 发起降落后选择脚下或附近合法落点；空中不能直接切回站立造成坠入地形。
- 首版主路线连续可走；少量高低地形丰富探索，不能阻断阅读内容。
- 室内可采用侧面剖视场景；房顶/边界和允许飞行区域由地图配置指定。
- 跨场景保持角色、位置和语言连续，避免切区后重置起点。
- 地图边缘、失败加载或意外越界应恢复到最近安全点。

### 4.4 输入优先级

旋转提示/阻断状态 → 内容面板 → 暂停菜单 → 正常游戏。

高优先级界面出现时，低优先级输入停止。页面失焦、切换应用、窗口调整、触摸取消均清除动作输入。后台恢复时限制时间步长，避免角色瞬间跨越场景。

## 5. 响应式与横屏

| 设备 | 横屏/窗口 | 竖屏 |
| --- | --- | --- |
| 手机 | 完整游戏、虚拟摇杆和动作按钮、紧凑 HUD | 已确认：旋转提示 + 经典版入口 |
| iPad | 完整游戏、适当留白、触控；兼容外接键鼠 | 按横屏要求规划为旋转提示；暂停并保留进度 |
| 电脑 | 自适应窗口、键鼠优先 | 小/窄窗口仍可访问目录和阅读内容，极小画布提示扩大窗口 |

- 游戏世界与 HTML 界面分别缩放；不能为适配宽高比把人物压扁或文字缩到难以阅读。
- 相机依据可用画布改变可视范围；飞行时可跟随高度，地面时避免镜头上下抖动。
- 手机横屏内容面板可覆盖大部分画面，打开后隐藏游戏控件；iPad/桌面使用较宽阅读面板。
- 刘海、安全区、浏览器地址栏变化与软键盘不能挡住关闭按钮。
- 旋转后保存 sceneId、世界位置、移动模式和面板内容；恢复时校验安全位置。
- 横屏使用提示引导，不以浏览器必须允许程序锁定方向或全屏为前提。

## 6. 中英双语

- 探索版全局提供 EN / 中文切换，并记住选择。
- 首次进入建议按浏览器语言选择中文或英文，未匹配时使用英文；显式用户选择优先。
- 切换覆盖加载页、旋转提示、按钮、操作说明、章节、对话、数据详情、空态和错误提示。
- 切换时保留角色位置、当前面板与阅读上下文，不重建整段旅程。
- UI 文案使用语言资源文件；可维护的个人资料翻译通过后台编辑。
- 默认以现有英文内容为基础，中文缺失时逐字段回退英文，不能显示空白或原始翻译键。
- 发布的必要界面和核心内容应有双语；回退用于兼容旧资料或后续新增资料。
- 中英文内容共享 ID、日期、排序、链接与技术标签，防止两份资料逐渐不一致。
- 正式名称可保持原文；简历语言按真实文件配置，不承诺自动翻译 PDF。

## 7. 数据与管理后台需求

### 7.1 已检查的事实

- Website_Public 与 Website_Admin 都是 React + Vite 项目，并各自初始化 Supabase 客户端。
- 两边代码均使用 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_ANON_KEY`；变量名相同不能证明运行环境连接同一项目。
- Admin 使用 Supabase Auth 获取会话，已登录后进入管理界面。
- Admin 直接对 projects、experiences、awards、skills 执行读取、新增、修改、删除、排序。
- Public 通过 `useCMSData` 直接读取上述表，部分 About、Hero、Contact 文案写在组件中。
- 当前项目图片按英文标题在代码中映射；双语与后台维护需改为稳定 ID/图片字段。
- 当前 EditModal 的默认值有 `visibility: public`，但未见可见性编辑控件；Public hook 未见可见性筛选。线上 RLS 是否已经过滤内容未知，不能据此断言发生泄露。
- 没有在检查到的代码中找到双语编辑、旅途配置、个人日记管理或文件上传流程。
- Website_Admin 没有发现独立 API 服务入口或数据库迁移文件；当前按前端直连 Supabase 的架构规划。
- 实际管理域名为 `admin.kaiusjin.com`，已验证该地址进入 `/login`，显示管理登录页；公开响应经过 Cloudflare，实际托管平台尚未确认。用户随后更正为“应该没有 Railway”，因此 Railway 不作为依赖或必需改造项。

### 7.2 必须纳入实施的配套改造

- Admin：现有四类资料的双语编辑、翻译完整度、保存校验与错误反馈。
- Admin：个人介绍、兴趣/日记、联系与简历配置的维护入口。
- Admin：七区标题、说明、内容绑定和素材引用的维护；首版无需通用地图绘制器。
- Admin：公开/草稿状态和探索版预览；草稿预览必须依赖有效管理身份。
- Supabase：兼容旧字段的增量迁移，必要的索引、约束和访问策略。
- Public：统一内容适配层，稳定 ID 关联、双语回退、公开内容筛选、加载失败和空态。
- 素材：版本化场景素材与可维护的照片/项目图/简历存储分工，记录 URL 和替代文本。
- 部署：沿用两站实际托管环境，核验构建、路由回退、环境变量和域名；本方案不要求新增独立 API 服务。
- 现有登录、编辑、删除和排序流程需回归验证；登录会话不能替代数据库侧管理员授权。

详细拟定字段、文件位置、迁移与部署顺序见配套实施计划。文档中的新表名和字段名是设计方案，不是已核实的线上结构。

## 8. 范围层级与质量目标

### 首版必须完成

R01–R13，七区最终素材与可读内容、基础角色动画、完整触控和键鼠操作、双语、后台配套、目录、加载与恢复、跨设备验证。

### 可后续增加

背景音乐与环境音、收集品、彩蛋、二段跳、冲刺、自由换装、多世界主题、跨设备探索进度同步。未经明确要求不把这些作为首版完成条件。

### 性能与维护目标（待实测校准）

- 桌面和较新 iPad 目标接近 60 fps；性能较弱的手机可降到稳定 30 fps，具体设备由实测定义。
- 首幕可交互所需压缩资源暂定控制在 8 MB 内，后续场景分批预取；以实际网络测量报告为准。
- 经典版入口不加载探索版引擎和场景素材。
- 图片加载失败有替代视觉与重试；数据失败保留目录、经典版入口和错误说明。
- 支持减少动态效果，保留跳跃/飞行功能并降低装饰粒子和镜头运动。
- 阅读面板可键盘操作，管理焦点，重要信息不只存在于 Canvas 或声音中。
